# Contexto

Você é um Desenvolvedor Front-end Sênior especialista em Angular. O projeto é uma Single Page Application (SPA) que servirá como um "Visual Query Builder" para o AWS Athena. O público-alvo são analistas de negócios que não sabem escrever código SQL. Como o AWS Athena cobra por dados escaneados, a interface deve forçar boas práticas de limitação de dados.

Quero construir um web app que funcione como um query builder.

# Objetivo

O objetivo desse web app é permitir que o usuário posso construir uma query apropriada para AWS Athena, sem necessáriamente saber SQL.

E para que isso funcione, precisamos de uma maneira de armazenar os inputs do usuário como parâmetros em JSON, que mais tarde podemos usar para gerar um script SQL

Criar a primeira versão funcional desta SPA em Angular. A aplicação não executará a query no banco, mas sim coletará as intenções do usuário através de componentes visuais e gerará um objeto JSON estruturado (payload) que será enviado posteriormente a uma API backend.

# Resumo

Em vez de gerar a string SQL diretamente no front-end (o que pode ser um risco de segurança e ser rígido demais), faça com que o construtor visual gere um objeto JSON (uma Abstract Syntax Tree - AST). Envie esse JSON para o seu backend, e lá você utiliza um parser para transformar esses parâmetros em uma string SQL segura usando a sintaxe do Trino/Athena antes de disparar a execução via SDK da AWS.

# Stack Tecnológica

* Angular (versão mais recente, preferencialmente usando componentes Standalone).

* `angular2-query-builder` (para a construção visual das regras lógicas da cláusula WHERE).

* SCSS (para estilização rápida e limpa).

# Requisitos da Interface (UX/UI)
A tela principal deve conter as seguintes seções em ordem de cima para baixo:

1. Origem dos Dados (FROM): Um campo de seleção (Dropdown) listando 3 tabelas fictícias (ex: `vendas_2023`, `clientes_ativos`, `log_eventos`).

2. Colunas (SELECT): Um grupo de checkboxes ou um multi-select que é atualizado dinamicamente com base na tabela escolhida no passo 1. Cada tabela deve ter pelo menos 4 colunas pré-definidas no código.

3. Filtros (WHERE): A implementação do componente ``. A propriedade config deste componente deve ser atualizada dinamicamente para mostrar apenas os campos correspondentes à tabela selecionada no passo 1.

4. Limite de Resultados (LIMIT): Um campo numérico (Input Number) com valor padrão de 100 e máximo de 1000.

5. Ação e Saída: Um botão "Gerar Payload" que, ao ser clicado, exibe logo abaixo o objeto JSON final gerado

# Pacotes essenciais

**ngx-query-builder (`angular2-query-builder`)**: é puramente open-source, bastante flexível e permite customizar completamente o visual dos campos, operadores e inputs. Ele mantém o estado da query em um objeto JSON (que representa a árvore lógica) perfeito para ser enviado ao backend e traduzido para o SQL do Athena.

# Notas sobre o ngx-query-builder

O `ngx-query-builder` (assim como a grande maioria dessas bibliotecas open-source) foca exclusivamente na criação de expressões lógicas e aninhadas. No mundo SQL, isso se traduz diretamente para a cláusula `WHERE` (e ocasionalmente para o `HAVING`).

Ele não gera a query inteira e não gerencia `SELECT`, `FROM`, `JOIN` ou `GROUP BY`.

Para construir um web app completo de extração de dados para o AWS Athena, o ngx-query-builder será a "peça central" da sua interface para lidar com a parte mais difícil da UX (as regras), mas você precisará compor o restante da tela com componentes tradicionais do Angular:

1. De onde buscar (FROM): Um dropdown simples para o usuário escolher a tabela ou conjunto de dados (ex: "Vendas 2023").

2. O que buscar (SELECT): Um componente de multi-select ou uma lista de checkboxes onde o usuário escolhe quais colunas quer ver no relatório.

3. Quais as regras (WHERE): Aqui entra o **ngx-query-builder**. Ele gerencia a complexidade condicional (ex: "Valor > 100 AND (Status = Ativo OR Status = Pendente)").

4. Agrupamentos e Limites (GROUP BY / LIMIT): Outros inputs simples opcionais no final da tela, caso o usuário queira limitar o resultado a 1000 linhas, por exemplo.

## O Fluxo de Dados (Angular -> Backend)
No Angular, você vai juntar os valores de todos esses componentes da tela em um único grande objeto de requisição e enviar para a sua API. O JSON ficará parecido com isto:

```JSON
{
  "tabela": "vendas_2023",
  "colunas": ["cliente_id", "valor_total", "data_compra"],
  "filtros": {
     // Aqui vai o objeto JSON gerado internamente pelo ngx-query-builder
     "condition": "and",
     "rules": [
       {"field": "valor_total", "operator": ">", "value": 100}
     ]
  },
  "limite": 100
}
```
O seu backend receberá esse payload, validará as informações (para garantir que o usuário não está acessando uma tabela que não deveria), fará o parse da parte dos filtros para SQL, e só então montará a string final: 

```SQL
SELECT 
    cliente_id, valor_total, data_compra 
FROM 
    vendas_2023 
WHERE 
    valor_total > 100 
LIMIT 100.
```

Essa arquitetura é na verdade a mais recomendada, especialmente trabalhando com o AWS Athena, que cobra por dados escaneados. Ao controlar o `SELECT` e o `FROM` fora do builder visual, você pode forçar no seu backend a sempre incluir um limite (`LIMIT`) ou obrigar o usuário a filtrar sempre por uma data particionada, evitando queries acidentais que custem milhares de dólares.

## Instruções básicas de como usar o ngx-query-builder

O pacote oficial no NPM é o angular2-query-builder.

O pacote principal que você utilizará se chama angular2-query-builder (apesar do "2" no nome, ele é mantido e compatível com as versões modernas do Angular).

1. Instalação
Abra o terminal na pasta do seu projeto Angular e rode o seguinte comando:

```Bash
npm install angular2-query-builder
```
2. Configuração Básica (Módulo)
Para que o Angular reconheça o componente, você precisa importar o QueryBuilderModule no módulo onde ele será utilizado (geralmente no app.module.ts, ou diretamente no seu componente se estiver usando a abordagem Standalone do Angular 14+).

```TypeScript
import { NgModule } from '@angular/core';
import { BrowserModule } from '@angular/platform-browser';
import { FormsModule } from '@angular/forms'; // Opcional, mas útil se usar ngModel
import { QueryBuilderModule } from 'angular2-query-builder'; // <-- Importe aqui

import { AppComponent } from './app.component';

@NgModule({
  imports: [
    BrowserModule,
    FormsModule,
    QueryBuilderModule // <-- Adicione aos imports
  ],
  declarations: [ AppComponent ],
  bootstrap: [ AppComponent ]
})
export class AppModule { }
```

3. Os Três Pilares (Componentes Principais)
Para o componente funcionar, ele precisa de duas variáveis no seu TypeScript e uma tag no HTML:

* `config` (A Configuração): Um objeto que diz ao builder quais colunas/campos existem, os tipos deles (texto, número, data, booleano) e quais opções exibir se for um select.

* `query` (O Modelo/Estado): O objeto JSON que armazena a regra atual que o usuário montou na tela.

* `(A View)`: A tag HTML onde a mágica acontece.

### No seu Arquivo TypeScript (`app.component.ts`)
Aqui você define o que o usuário pode filtrar.

```TypeScript
import { Component } from '@angular/core';
import { QueryBuilderConfig } from 'angular2-query-builder';

@Component({
  selector: 'app-root',
  templateUrl: './app.component.html'
})
export class AppComponent {
  
  // 1. O ESTADO ATUAL (O que o usuário já escolheu)
  public query = {
    condition: 'and',
    rules: [
      { field: 'idade', operator: '>=', value: 18 }
    ]
  };

  // 2. A CONFIGURAÇÃO (As opções disponíveis para o usuário)
  public config: QueryBuilderConfig = {
    fields: {
      idade: { name: 'Idade', type: 'number' },
      nome: { name: 'Nome', type: 'string' },
      status: {
        name: 'Status da Conta',
        type: 'category',
        options: [
          { name: 'Ativo', value: 'ativo' },
          { name: 'Inativo', value: 'inativo' }
        ]
      }
    }
  };
}
```

### No seu Arquivo HTML (`app.component.html`)
Por fim, adicione o componente visual na sua tela e conecte as variáveis que você acabou de criar.
